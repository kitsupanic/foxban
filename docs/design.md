# Design

User-facing behavior only. Technical mechanics live in [architecture.md](architecture.md).

## Screens

- **Board list** — create a board with a name and unique uppercase key (2–10 alphanumeric characters starting with a letter), plus an optional appearance chosen from twelve named Lucide icons and eight named colors. The modal previews the live draft; icon and color persist for every member and can be changed later through **Edit** by the board owner or an account admin. Existing boards use the neutral square-kanban/slate appearance; new boards default to square-kanban/amber. Rows show the persisted decorative icon tile, linked name, adjacent key, optional repository link, and a settings menu containing **Add member** for members plus **Edit** and **Delete** where existing owner/admin predicates allow them. A board row carries no GitHub controls: repositories belong to the instance (ADR 0064).
  - _Members_: **Add member** opens one searchable dialog. **Already added** lists current members; the owner is marked **Owner**, admins are marked **Admin**, the viewer is marked **You**, and each other member has **Remove** behind a row-local confirmation. Cancel or Escape restores the row action; confirmed removal keeps the dialog open, announces success, and moves that person into **Add someone**. Owners and viewers cannot remove themselves. Removal revokes later guarded requests and WebSocket reconnects; a socket already connected remains live until reconnect.
- **Shared header (Boards & Profile)** — the two top-level pages carry one header: **Boards** and **Profile** links, your avatar and email, and **Sign out**. The links are plain URL-backed navigation, not ARIA tab widgets — the page you are on is announced through `aria-current="page"`. The board reuses this workspace navigation with **Boards** current, a compact 64px rail by default, and **Expand navigation** / **Collapse navigation** switching to and from the 184px sidebar for this session. Its breadcrumb reads `Workspace › Boards › <board name>`; **Boards** links to `/`. At 600px and below, the board shows one compact banner with the brand mark, readable workspace switcher, **Menu** disclosure and account action. Menu opens labelled workspace/account links above the board without moving its content; Escape returns to its trigger, outside clicks dismiss it, and board shortcuts do not fire while navigating it. The redundant board breadcrumb hides at this width. Collapsed desktop icons expose labels on hover and keyboard focus, including the current workspace name; hints are hoverable and Escape dismisses them. Expanded navigation and the phone Menu show their text labels directly. Workspace and account menus focus their first item on Enter/Space/ArrowDown, or last on ArrowUp; arrows wrap, Home/End jump and typing finds a name. Escape closes and returns to the opening button; Tab/Shift+Tab dismiss into the normal page order. Only the active surface renders its menu, linked to its actual trigger; workspace selection stays URL-backed and marks the current workspace.
- **Profile** — a dedicated authenticated `/profile` page with a clear page heading and six independent sections (Avatar, Display name, Sign-in email, Password, GitHub, and Timezone). Each owns its button, pending state, error and success message; submitting one never sends or clears another's drafts. Pending buttons use active verbs and disable only themselves. Success is a polite status, errors are alerts, and editing that section again clears stale feedback.
  - _Avatar_: displays current avatar preview (uploaded, GitHub, or initials) and options to upload or remove a custom profile picture. Image uploads accept PNG, JPEG, GIF, and WebP up to 10 MB, prepared client-side to WebP at quality 0.8 with longest side at most 512 px. Removing an avatar restores GitHub or initials fallback.
  - _Display name_: one name field and **Save name**. On success ("Name updated.") the shared header and every member surface pick the new name up.
  - _Sign-in email_: the new email plus your current password, and **Change email**. A wrong password reads "Current password is incorrect."; a change that would alter administrator access (in either direction) reads "Email changes cannot alter administrator access."; a taken email reads "That email is already registered." Success ("Email updated.") keeps you signed in — the credential did not change.
  - _Password_: current password, new password (8–256 characters; common passwords, repetitions of 1–4-character units, and contiguous ascending or descending alphanumeric runs are rejected) and a confirmation; a predictable password or mismatch is rejected on the client ("Choose a less predictable password." or "New passwords do not match.") without calling the API. Success reads "Password updated. Other sessions were signed out.": the change revokes every other session for new HTTP requests and new socket handshakes, while an already-open board socket lives until it reconnects — the same connect-time-only semantics member removal has.
  - _GitHub_: unconnected, it offers one **Connect GitHub** button: it takes you to GitHub, asks you to authorise foxban, and brings you back to Profile wearing your GitHub picture on every avatar of you across the app. Connected, it reads "Connected to GitHub as `<login>`" with a **Disconnect** button that puts the initials circle back. A connection you cancel or that fails lands back on Profile saying "GitHub connection failed." — usernames cannot be typed in, so the picture is always the account you proved you hold.
  - _Timezone_: a searchable accessible combobox/listbox with `Automatic (<browser zone>)` (or `Automatic (unavailable)`) pinned first, followed by available IANA timezones in alphabetical order. The search input implements full combobox semantics (`role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` linked to the listbox id). Typing filters matches case-insensitively; Arrow keys walk options with clamping; Enter selects; Escape clears search query or closes panel; outside clicks dismiss. Saving an explicit timezone or resetting to Automatic displays "Timezone updated." and reconnects the app-wide presence socket with the updated effective timezone.
- **Sign in / sign up** — both share one centred white card topped by a pale amber band with the fox mark and the page title; the submit button and links use the workspace amber. The login form links "Have an invite? Sign up". `/signup` keeps its form whether or not a link is present (an admin-domain email signs up directly), but says up front when there is none: "No invite link detected — ask an admin for one if you need an account." Signup passwords enforce the same 8–256-character and predictable-pattern policy (common passwords, 1–4-character unit repetitions, and contiguous alphanumeric runs rejected) with immediate local and API validation ("Choose a less predictable password."). Existing weak passwords remain valid for login.
- **Board view** — public board URL is `/board/:boardKey`. Above 600px, 278px columns run left-to-right with 18px gaps and horizontal overflow inside the canvas; cards stack within each pale column. The identity row has a 40px tile using the board's persisted icon and colour, the board name, its monospace uppercase key underneath, and a separator before connection state: `Live` with a green dot, `reconnecting…`, or `Could not connect.` with **Retry**. **Members** shows `Members · N` after a successful nonempty member query; the amber Plus action reads **New card**. The bordered toolbar contains a 240px desktop **Search cards** field with Search icon and `/` keycap, **Assigned to me** with a user icon and `M`, one **Filters** control with sliders icon and accessible name **Filter cards**, the loaded `<matching> of <total> cards` count, then **Archive** with a nonzero archive count and the **Keyboard shortcuts** help control. Counts come from loaded state, not placeholder zeroes. A white card front has a 5px type-coloured rail and a top row containing its sentence-case type badge and icon, monospace `<KEY>-<NUMBER>` identifier (omitted until server numbering), and right-aligned drag grip. The 14px title follows, then wrapping real label pills, then the optional due date on its own row. The footer starts with priority, followed by relation state, the checklist `done/total` fraction, and optional pull request, comment, attachment and video indicators; the 24px assignee avatar sits at the right. Epic is purple, Subtask teal, Spike blue, Task yellow and Bug red. Due dates retain **Today** and **Overdue** wording and viewer-local date semantics. Pull request badges remain passive, show the state of the card's pull request that is still in play (open, then draft, merged, closed) with a count when there are several, and appear identically in the drag preview. Linked subtasks remain in their parent's family rather than becoming separate root cards.
  - _Column permissions_: only this board's owner or an account admin sees Add, Rename, Move and Delete column controls. The header groups a small grey dot, title and passive count on the left, with Plus and a manager-only ⋯ menu on the right. For managers the dot is the focusable **Move column <title>** drag handle; **Column actions for <title>** opens **Rename** and **Delete** with arrow-key navigation and Escape/outside dismissal. Rename opens the inline title editor; clicking the title or focusing it and pressing Enter does the same. Members see passive, non-focusable headings and no trailing Add-column slot, but retain cards, empty-column drop targets, header Plus and footer **Add card**. Both card actions open **Create a card** with that column selected. Empty columns say **No cards yet** above Add card; a nonempty column whose cards are filtered out says **No matching cards**. Managers have a trailing dashed **Add column** action with Plus and a `C` keycap.
  - _Permission-loss cleanup_: when the client owner/admin predicate becomes unavailable or false, an open title editor discards its local draft without sending; an open column-delete confirmation dismisses and releases workspace inertness. Deferred focus returns to the footer **Add card** for title dismissal or **Search cards** for delete dismissal only if focus is free, never stealing another field's focus. An open **Add a column** dialog disables submission and says "Only a board owner or an admin can add a column." Regaining permission does not reopen a discarded editor or confirmation. This rendering cleanup is not live server-role revocation.
  - _Phone workspace_: at 600px and below, search fills the first toolbar row; **Mine** (accessible name **Assigned to me**), **Filters**, **Archive** and help share a compact second row. **Workflow**, **Members** and **New card** share a row below board identity, with New card on the right; the workflow control retains the accessible name **Workflow settings**. Header and canvas use 16px horizontal gutters. Columns and the manager's trailing Add column action use the full available width, stacking vertically with 16px gaps and document scrolling. Column keyboard reordering uses Up/Down here and Left/Right above 600px. The whole card remains the delayed touch drag surface: deliberate movement uses a 250 ms hold, short swipes scroll, and mouse dragging and Space/arrow keyboard movement retain the full card surface. Cancelling an activated pointer drag with Escape also consumes that gesture’s eventual release click, even after a long hold; it never opens the card. A fresh pointer click or keyboard activation still opens normally.
  - _Tablet workspace_: above 600px, identity and the bordered toolbar remain separate wrapping rows, with 26px horizontal header and canvas gutters. Columns stay horizontal; there is no separate `md`/`lg` header layout. The member rail uses its independent 768px breakpoint. **Filters** and **Keyboard shortcuts** remain available at every width.
  - _Coarse-pointer board controls_: under `pointer: coarse`, workspace buttons and links, dialog buttons, **Search cards**, column-title inputs and dialog text inputs have at least 44px hit heights. Account and dialog-close icon controls use 44×44px targets. Fine pointers retain compact controls.
  - _Member presence sidebar & drawer_: a right-hand rail displays actual board members with Foxban avatar, name, live online/offline indicator, local time, and last-online timestamp. At 768px and above, **Members** toggles the fixed 256px rail beside the Kanban and safely persists visibility in `localStorage` (`foxban-member-rail-visible`). It defaults hidden when no preference exists or storage is blocked; an existing preference is preserved. Hiding it lets the canvas claim that width. Below 768px, **Members** opens an accessible overlay drawer (`role="dialog"`, `aria-modal="true"`). Online members sort first, followed by offline members, preserving name order within each group. Status reads `Online`, `Last online <relative time>` (`just now`, `<N>m ago`, `<N>h ago`, `<N>d ago`), or `Last online unknown`; local time reads formatted `H:MM AM/PM` in each member's effective timezone or `Local time unavailable`. Color is never the sole indicator of status.
  - _Search_: one search field leads the bordered toolbar, with stable accessible name **Search cards** and placeholder "Search cards…". It searches `card.title` only, immediately matching `query.trim().toLowerCase()` as a case-insensitive substring; non-matching card fronts hide while every column and Add card action remains. Search intersects with both the `?labels=` and `?assignees=` filters (AND), never widens them. Its raw value lives in `?q=`, replaced on every edit so it survives reloads, shared links, and opening or closing a card without filling the Back stack. `/` focuses it only when the event target is not an input, textarea, select or contenteditable element, no overlay is open, and no drag is active. Escape clears a non-empty query while retaining focus, then blurs an already-empty field.
  - _Assignee filters_: **Assigned to me** is an exact-scope shortcut: when inactive it replaces the assignee dimension with the signed-in user's id, and when active it clears that dimension. **Filters** opens one combined label/assignee dialog at every width: centred and 450px wide above 600px, a bottom sheet at 600px and below. It stays open while name-ordered members or **Unassigned** are toggled; those selections are ORed, then intersect with search and labels. Its raw comma-joined selection lives in `?assignees=` (`none` means unassigned), survives reloads, shared links and card navigation, and filters directly from card snapshots even while member metadata is loading or failed. Label and assignee choices expose `aria-pressed` matching visible checkmarks and URL state; the existing no-label choice, scoped retry and **Clear filters** remain in the same dialog.
  - _Filter feedback_: the loaded toolbar reports `<matching> of <total> cards` even without filters above 600px; phones hide only the redundant unfiltered count. Active filters keep the count and **Clear filters** visible at every width. Zero matches say "No cards match the active filters."; they never resemble a genuinely empty board. The Filters trigger exposes its expanded state; the dialog traps focus, closes on backdrop interaction or Escape and restores trigger focus.
  - _Column card counters_: each column title has a passive counter of active cards, including zero. Any effective search, label or assignee filter changes it to visible matches / total (`1 / 3`), even when all or none match. Whitespace-only search and stale label tokens do not activate it; archived cards never contribute. The counter remains visible during renaming, stays outside the heading's accessible name, and adds no keyboard focus stop.
  - _Loading failures_: board metadata and member-list failures name the missing data and offer a scoped retry. They never settle indefinitely on `…`, silently empty the card or board assignee picker, or leave an unexplained `?`; these HTTP failures remain distinct from WebSocket connection state.
  - _Add a column_: **Add column** or `c` opens **Add a column**, with "Give this stage of your workflow a name.", **Column name**, placeholder "e.g. In review", **Cancel** and **Add column**. The name starts focused, is trimmed, must be nonempty and has a 200-character limit. Opening creates nothing; submitting appends after the latest board-order column and remains owner/admin-only.
  - _Create a card_: **New card** or `n` opens **Create a card** for the first sorted column; the column's Plus or **Add card** preselects that column. With no column, New card is disabled with "Add a column before creating a card." and `n` does nothing. The dialog says "Add a card to <board name>.", focuses **Title** with placeholder "What needs to be done?", then presents **Type** / **Column** and **Priority** / **Assignee** in reading order. These are the existing pickers in two columns, stacking into one at 600px and below. Defaults are **Task**, the opening column, **Medium** and **Unassigned**; Type also offers **Epic**, **Spike** and **Bug**, not Subtask. Title is trimmed, required and limited to 200 characters. **Create card** submits all selections together at the selected column's latest unfiltered tail and reads "Creating…" while pending. Member loading says "Loading board members…"; failure says "Could not load board members." with **Retry members**. Unassigned remains usable, but a removed selection is not silently cleared: "That column is no longer on the board. Choose another one." or "The selected member is no longer on this board. Choose again." disables submission until corrected.
  - _Creation settlement_: both creation dialogs trap focus. Before submission, **Cancel**, **Close dialog** (X), Escape or backdrop dismissal discard only the transient draft and send nothing; reopening starts clean. An open picker handles Escape before the dialog. Once sent, fields, submit, Cancel and X lock, and Escape/backdrop cannot dismiss the pending request. Only server acceptance, including confirmation from an authoritative reconnect snapshot, closes the dialog; an optimistic row is not confirmation. A failed send retains an editable draft with "Not connected — changes won't send."; rejection retains it with the server error. Timeout or uncertain delivery keeps submitted values locked with "Checking whether creation completed…". Confirmed absence unlocks the same draft with "Creation was not confirmed. You can try again."; retry is explicit, never automatic. Connection failure shows **Could not connect.** and a **Retry** that remains usable while creation is pending, so reconnect can verify the request. Closing restores the opening control, falling back to an available New card, Add column, Add card or Search cards control if needed. These transient dialogs add no URL state.
  - _Keyboard shortcuts dialog_: the help control opens **Keyboard shortcuts** at every width with "Move around the board without leaving your keyboard." Its seven divided rows read **Search cards** — `/`; **Add card to first column** — `N`; **Add column** — `C` (owner/admin only); **Assigned to me** — `M`; **Pick up focused card** — `Space`; **Move picked-up card** — `← → ↑ ↓`; **Close or cancel** — `Esc`. Members see six rows. **Close dialog** (X) starts focused; Tab stays inside, and X, Escape or backdrop dismissal restores the help trigger.
  - _Column delete_: **Delete** in the manager's column-header ⋯ menu opens a centred destructive alert naming that column. An empty column says it will be permanently deleted; a populated column states the unfiltered active card count and that those cards remain in **Archived cards** for 90 days. `Cancel` receives initial focus; Cancel or Esc closes and returns focus to the ⋯ trigger, while a click on the overlay does nothing. The board and shortcuts stay inert behind the alert. `Delete column` sends only while connected, removes the column and its cards from the active board, and leaves every card aggregate recoverable. A live peer deletion dismisses a stale alert. If browser history restores a URL-backed card while the alert is open, the card route takes precedence.
- **Archived cards** — an always-visible toolbar button with accessible name **Archived cards** reads `Archive` or `Archive N` for a nonzero count and opens a centred modal with Close initially focused. Newest archived cards appear first with their title and former column, remaining retention days, and their persistent muted `<KEY>-<NUMBER>` task identifier beside the title. Each row restores independently through a native destination-column select; no live columns leaves restore disabled with "A board owner or admin must add a column before archived cards can be restored." When a manager adds a destination, the member can restore without closing or reloading the dialog. Beside Restore, **Delete permanently** opens an inline warning that the card and everything on it cannot be recovered, with **Delete permanently** and **Cancel** actions. Cancel or the first Escape restores focus to the row action; a second Escape closes the archive dialog and restores its toolbar trigger. A disconnected delete leaves the confirmation and row intact.
- **Card details modal** — a sticky header (the non-editable muted `<KEY>-<NUMBER>` task identifier immediately before the title region, the title field, a fullscreen toggle button with stable accessible name `Exit full screen` when expanded and `Full screen` when collapsed, and a close button), a two-pane body — description, checklist, subtasks and Activity in the main column, one full-height Details pane on the right containing essential metadata and Labels/Contributors/Development/relations/attachments (independent main and Details scrolling at `md` and wider when the viewport is at least 600px tall) — and a sticky footer carrying **Close** and **Save title & description**, all inside a `max-w-6xl` overlay panel capped at the viewport height. Below `md`, both modal modes use one safe-area-aware dynamic-viewport surface: Status, Type, Assignee, Priority and Due date lead the single scroll before description, checklist, subtasks and Activity; advanced details follow. The Clear split layout places muted labels above white value controls on a pale Details surface, with one property column on desktop and two on phones (Due date spans both). Controls retain visible chevrons, hover/focus feedback, their DOM/keyboard order and at least 44px hit heights on phones and coarse pointers. Wide windows shorter than 600px also use this shared scroll so lower controls stay reachable. The semibold task title is 20px on phones and 24px on desktop windows; it wraps beside its edit/action/close controls with the monospace task key and live task-type label above it. The redundant fullscreen toggle hides below `md`; The text-save and Close actions remain in the fixed footer. Resizing retains the same mounted editor and its draft. Topmost focus containment: CardModal, CardArchiveDialog, attachment fullscreen viewer, and transfer dialog cycle Tab/Shift+Tab strictly within the topmost active surface; active-container inert checks prevent nested dialogs (such as the description edit confirmation or attachment viewer) from leaking focus to the parent card modal. When the attachment fullscreen viewer closes, focus returns to the actual connected invoking card control (or operable card fallback). Labels precede native **Contributors**, **Development**, **Relations** and **Attachments** disclosures. Contributors, Relations and Attachments start collapsed; the latter two retain their counts in the visible summary. Contributors displays **Created by** and **Assigned during this task** avatar rows with a Former Member fallback when opened. Empty Development starts collapsed; a connected repository starts expanded. Disclosure content stays mounted, retaining any independent draft or pending work. Empty Checklist and Subtasks use compact heading/action rows. **Add item** reveals and focuses the checklist input; Escape collapses an empty input and restores the action only if focus has not moved elsewhere. Nonempty input stays available. Populated content expands naturally. Section typography is scoped to interface headings: 15px main headings, 13px secondary disclosure headings and 14px description/comment text on desktop, with 16px description text on phones. Muted 16px section icons, clearer section spacing, flat comments, a taller compact comment entry with its own action below, and an amber Activity underline follow the selected Clear split concept. Markdown heading levels remain authored content. The modal inherits the workspace palette even when portaled outside the workspace shell.
  - _Open_: a click on a card body. Not a drag (dnd-kit's 4px activation swallows the trailing click).
  - _Save_: **Save title & description** sends one update carrying only the changed title/description fields and is disabled when neither has a meaningful edit. Enter in the title and Ctrl/Cmd+Enter in the description use that same text-only action; unchanged text does not save or close the card. The separate footer **Close** uses the same dirty guard as the header close button. Each changed text field carries an **Unsaved** badge, and the footer identifies **Unsaved title**, **Unsaved description**, or **Unsaved title and description**. A clean text draft reads **Title and description are up to date.**; other authored drafts instead read **Other drafts have their own save actions.** The essential-details block says **Changes here save automatically.** while connected and **Automatic saving is unavailable offline.** while disconnected; these are capability hints, not server-acceptance receipts. The footer never claims the whole card is saved. Pending saves, upload/deletion activity, offline failures, uncertain delivery, rejection and recovery retain their own messages and existing guards. When a description exceeds 100,000 UTF-8 bytes, the footer shows a destructive alert **Description must be 100,000 bytes or fewer.**, prevents sending, and retains the draft for correction. Saving commits only title and description drafts; unposted comment, edited comment, reply, subtask and pull-request-link drafts use their own actions and keep the card open after text acceptance. Saving is acceptance-aware: the card closes only upon authoritative server echo or snapshot acceptance when no other authored work remains. The busy action reads **Saving…** and locks title/description until settlement. Closing a dirty card raises **Discard unsaved changes?** with **Changes already saved will stay.**; pending authored writes additionally explain **Leaving won’t cancel changes already submitted.**. The prompt initially focuses **Keep editing**, and cancelling returns to the invoking control (or a connected Close fallback) without overriding a newer focus owner. Existing Escape/discard behavior remains.
  - _Description_: Markdown (ADR 0013), shown rendered. Text remains selectable and copyable on ordinary clicks; double-clicking does not edit. Triple-clicking non-interactive rendered text opens an "Edit description?" confirmation modal with Edit, Cancel, and Don’t ask again; clicking Edit enters edit mode, and if Don’t ask again was checked, persists `foxban-skip-description-edit-confirmation` so subsequent triple-clicks edit immediately. Dismissing the confirmation via Cancel, Escape, or backdrop click closes only the confirmation and never persists the preference. Explicitly clicking **Edit** beside the Description heading (accessible name **Edit description**) or the muted "Add a description…" placeholder enters editing immediately without confirmation. A single click on an embedded card-attachment image opens the same URL-backed fullscreen attachment viewer as its sidebar thumbnail, while external, non-image, and stale images remain plain. Below the textarea, an editing-only live counter shows `<used> / 100,000 bytes` (in muted text within the limit and destructive styling on overflow). Each button is a plain insert around the selection (no toggle-off); **Preview** — or Esc, which backs out one level rather than closing anything — returns to the rendered view as a preview of the *uncommitted* draft, so persisting still needs **Save title & description**. The editor also says **Preview doesn’t save your edits.** Ctrl/Cmd+B and Ctrl/Cmd+I mirror the bold and italic buttons. The image button picks a file, and pasting an image from the clipboard does the same: it uploads, attaches, and splices `![name](url)` at the caret. Raw HTML in a description is shown as literal text and never rendered as elements, and `javascript:` links are stripped.
  - _Save with an emptied title_: an empty title is treated as a slip, not an edit — the card keeps its old title and only a description change is sent.
  - _Discard_: Esc, a backdrop click and the header close button all close a clean modal at once, without sending. With unsaved work — a title or description differing from the card, a comment or reply being composed, changed comment-edit text, in-flight Markdown uploads, or pending/uncertain/recoverable operations — they instead raise a strip in the footer, "Discard unsaved changes?" with `Discard` and `Keep editing`; a further Esc discards, and typing in the title or description dismisses the strip. The same guard covers a relation, parent or subtask row, since opening that card replaces the modal (ADR 0020). Browser history navigation (Back/Forward) or programmatic routing away from a dirty card modal is similarly intercepted by a custom navigation blocker presenting "Discard unsaved changes?": `Keep editing` cancels the navigation and preserves all drafts and in-flight work, while `Discard` confirms the navigation. Same-card presentation changes (`view=full`), filter adjustments, and attachment preview transitions are exempt from blocking; cross-route or cross-board navigation remains blocked even if referencing the same card.
  - _Fullscreen_: a header toggle button trades the overlay panel for the full viewport and nothing else — the same header, the same two-pane body with the same sections in the same places, the same footer, only on a wider surface (its content capped on a centred `max-w-5xl` column). The button collapses back to the modal, and the card keeps whatever is typed either way. The open card, its presentation and a previewable image live in the URL — `/board/:boardKey?card=<BOARD_KEY>-<TASK_NUMBER>&view=full&attachment=<id>` — so the view is shareable and a reload lands back in it, with Back peeling the viewer off the card. `attachment` is reserved for exact PNG, JPEG, GIF and WebP metadata; a missing card, an attachment the card does not carry, or any non-image attachment drops the param and leaves the card open.
  - _Concurrency_: authored operations (title/description Save, comment submission/editing, reply submission) are acceptance-aware: `ws.send` is not completion; server echo or snapshot is authoritative. The relevant editor lane locks read-only while pending or uncertain, keeping the submitted payload visible byte-for-byte and preventing the user from creating a divergent draft in that lane while settlement is in flight. Unrelated composer lanes remain editable. If an authored operation times out or disconnects, the socket initiates an authored-only reconnect and resynchronization to obtain a fresh authoritative snapshot, without automatic resend or offline queuing. If the snapshot contains the mutation, it settles as accepted and clears or closes only the matching editor; if the snapshot verifies the mutation is absent (or on explicit server rejection), the editor unlocks and retains the exact raw draft, displaying an inline recovery alert with explicit `Retry` ("Retry unsent save", "Retry unsent comment", "Retry unsent reply") and `Discard` actions. Raw editor text is distinct from normalized wire body to preserve exact user formatting on retry. Late acceptance cleans up terminal recovery and never duplicates an entity. If another user deletes the card meanwhile, the modal closes.
  - _Draft vs instant_: title and description are a Save-committed draft (above). Status, assignee, priority, due date, labels, relations, attachments and comments are not: they are discrete mutations, so each one applies instantly through the normal optimistic mutation path and renders straight from the live board cache — a draft there would only buy a merge story nobody asked for.
  - _Status_: the first sidebar field is a Jira-style listbox showing the current column title. Its options are every live column in board order, with the current one checked. Choosing another column instantly sends the existing `card.move` mutation, appends the card after the destination column's active cards, keeps the card open, and updates live for every member; choosing the current column is a no-op. Escape closes only the picker, arrow keys walk its options, and outside interaction dismisses it.
  - _Type_: immediately following Status, a listbox picker displaying a root card's first-class type with options Epic (purple), Spike (blue), Task (yellow), and Bug (red). Instant-save like Status, sending `card.retype` only when changed; the creation dialog defaults to Task but allows a different root type before submission. A subtask instead has the fixed type **Subtask** (teal), shown read-only with no picker; it cannot be retyped. Card fronts show the type as a 5px left rail and an icon-and-name badge in the top row.
  - _Assignee_: a custom Jira-style picker, not a native select — a flat, visibly labelled button showing the member's avatar and name (a dashed empty circle and a muted "Unassigned" when nobody holds the card), opening a panel with a type-to-search input filtering board members (`GET /boards/:id/members`) by a case-insensitive substring of name or email, an always-present `Unassigned` row pinned above the matches whatever the query, and one avatar-and-name row per match carrying a check icon on the current choice. Enter picks the first match, Esc clears a non-empty query and only then closes, a click outside closes, and arrow keys walk the rows. Choosing a different entry sends `card.assign`, where `null` means unassign, and applies instantly. One assignee per card. An a…
  - _Priority_: the same button-and-listbox pattern — a flat, visibly labelled button showing the level's coloured Lucide icon and name, opening a panel of the five Jira levels (Highest, High, Medium, Low, Lowest), each with its own coloured icon and a check icon on the current level, walked with the arrow keys and closed by Esc or a click outside. There is no empty entry; choosing a different level sends `card.prioritize`. Every card has a priority and none can be cleared: creation defaults to Medium unless another level is selected (ADR 0016).
  - _Due date_: the browser's native date input (no datepicker dependency); picking a day sends `card.schedule`. Optional and clearable, unlike priority — most cards have none, and the clear button beside the input (or emptying the input) removes the deadline. An empty unfocused field displays **No due date** through an aria-hidden visual overlay; focusing exposes the unchanged native date segments. A date only, no time of day, so the deadline is the same day for every member; whether it reads as overdue or due-today is judged in each viewer's own timezone (ADR 0017).
  - _Labels_: instant-apply, independently of the card footer Save. Board cards and ticket details share compact pale tinted chips with a small colour dot and wrapping names; the details chips retain a visible remove button that unassigns only this card. **Add labels** opens a searchable chooser beside its trigger without moving the current scroll position, listing board labels with toggle checks and per-label Edit actions. Selecting keeps the chooser open; arrow keys move between search and toggles, and Enter toggles the focused row or first search match. **Create label** reveals the name, eight subdued colour choices, a live chip preview and **Create and add**; successful creation assigns the label and returns focus to search. Editing uses the same palette/preview and preserves partial rename/recolour updates. Board-wide Delete remains behind “Remove this label from every card?” and explicit Delete/Cancel. Done closes the chooser. Escape backs out one stage at a time: delete confirmation, editor, search text, chooser, then the card. Outside dismissal retains the active creation/edit draft for reopening; explicit creation Cancel clears it. The first backdrop click dismisses the chooser before the card. Name fields retain the shared 200-character bound; phone controls retain coarse-pointer touch targets.
  - _Relations_: the counted native disclosure starts collapsed and retains its mounted content. Inside it, "+ Link a card…" reveals the composer with a dedicated link action. Opening it gives a kind select (Related to / Blocks / Blocked by) and a type-to-search card picker filtering board cards by case-insensitive title substring or exact task key/number (e.g. `FB-2` or `2`), sorting exact task identifier matches first and capped at eight results. Clicking a result or pressing Enter for the first match sends immediately and leaves the composer open with an empty query. Esc backs out one stage at a time: it clears a non-empty query, then collapses the composer, and only then reaches the modal. Each relation row opens the card at its other end; a remove button removes the link (ADR 0018).
  - _Subtasks_: a subtask is a real card with immutable type **Subtask**, linked by a `subtask` relation row ("source is the parent of target"). A subtask cannot create or link another subtask, so families have one child level rather than recursive nesting. Completion remains its own flag. The entity appears in two places: a full-width disclosure footer inside its parent's card on the board, and the Subtasks section of the parent's details. The board footer shows only when the root has children — chevron, `Subtasks`, and a right-aligned `done / total` count — and opens bordered child rows with no connector rails. Each row carries a vertically centered 16px completion control, a 12px title over an 11px muted task ID, and the parent's own borders, so a family reads as one card rather than loose cards. Every family starts expanded; collapsing one is remembered for the board session only.

  - _Checklist_: heading shows `done/total` once there is an item, followed by a rounded whole-number percentage and a horizontal progress bar; cards with no items show neither progress treatment. The card-front badge instead shows the exact `done/total` fraction, with tooltip and accessible label `Checklist: <done> of <total> done`. A checkbox toggles an item; a click on the item text opens an inline editor that submits on Enter or blur and cancels an editable draft on Esc. Empty or overlong text stays editable with an inline validation error; an unchanged edit closes without sending. Creation and text edits retain exact raw drafts until server acceptance: pending or uncertain submissions lock only their own input, and rejection, disconnection or verified absence preserves the text for explicit retry. Pending inline text cannot be cancelled or replaced by another item editor; leaving the card retains the existing explicit discard warning. Unsent text joins the modal close guard. If a peer deletes an edited item, its draft remains available to save as a new item or discard. A convert button converts an item into a subtask card (see _Subtasks_ above) and a delete button deletes it; the composer appends one on Enter and clears only after acceptance. With no items, **Add item** beside the heading reveals the composer below; populated lists keep it below their items. The input and **Add item** button share a spaced row with matching heights and 44px phone controls. Item rows have clear hover/focus feedback, and long unbroken text wraps inside the available width.
  - _Attachments_: the counted native disclosure starts collapsed and retains its mounted content. Arbitrary files attach from the card panel with **+ Attach file** and apply instantly like the checklist. Declared PNG/JPEG/GIF/WebP images are limited to 10 MB after best-effort client-side downscaling/WebP compression; every other declared or unknown type is limited to 50 MB (ADR 0028). The heading shows the count. Image rows keep the 40 px thumbnail, file name, size and URL-backed fullscreen viewer with **Open original**; non-images use a generic file icon tile and a same-origin filename download link instead, without opening a tab or viewer. That intended row click supplies the original filename to the browser; a copied raw UUID URL does not. Every row's delete button first opens an inline **Delete? / Delete / Cancel** confirmation; Cancel or Esc restores the row action, while Delete removes the attachment from the card, the server and R2.
  - _Attachment deletion and the description_: a confirmed deletion also removes that attachment's own Markdown embeds from its card's description, so nobody is left with a broken image. Images and their alt text go; a link keeps its label as plain prose. Only exact references to that attachment are touched — another attachment, a copied link on a different card, code samples and comment history all stay. The removal reaches the saved description in the same server write as the deletion (no second save, no extra history row) and every member's rendered view updates live. An open editor keeps everything typed: the reference disappears from the draft, the surrounding prose and any unsaved title stay, and Discard still persists nothing. While a deletion is in flight the footer reads "Deleting attachment…" and Save is held for that card only — a rejection or timeout puts both the row and its reference back, and a reconnect settles a deletion whose confirmation was lost.
- _Activity_: the white section spanning the main column at the bottom of the card contains **All**, **Comments**, and **History** tabs and opens on **Comments** whenever a card opens. All tabs order top-level rows by immutable creation date. A sibling sort button reads **Oldest first** initially and toggles to **Newest first**; the chosen direction reverses top-level items while reply threads stay oldest-first. Tab counts reflect active comments, arrow/Home/End keys move and select focus, and switching views preserves in-progress drafts. Authored comments support one-level reply threads: replies appear indented directly below the root in chronological order, with reply-to-reply flattened as a sibling under the root. A tombstoned root displays an italicized `Comment deleted` placeholder retaining its replies until all replies are deleted. Live comments provide a `Reply to comment` action opening a dedicated inline reply composer. Submitting a comment or reply locks only its own composer lane read-only while pending or uncertain with button text "Sending…", while unrelated lanes remain editable. The root composer always shows an inline **Add a comment…** textarea and its own disabled-until-usable **Comment** action. Focus or typing expands the same mounted editor with formatting controls; Cancel or the first Escape collapses an editable draft, clears transient editor feedback and retains the textarea. A second Escape reaches the modal close/dirty guard. Uploading, pending and uncertain work retains its existing guards. Comment dates use compact month/day text with the full timestamp available to assistive technology and on hover. The comment composer submit button carries stable accessible name `Save comment` (labeled "Comment"). Author-only edit and author-or-admin delete permissions apply to roots and replies alike. In-flight image uploads in Markdown editors are authored work: submissions wait for upload insertion; closing, navigation, and Save preserve them. If a peer deletes a target comment while a reply has an image upload in flight, the upload is preserved without destructive child-to-root reanchoring; upon completion, detecting the deleted target produces a single explicit orphan recovery banner: "Target comment was deleted by a peer. Reply draft preserved (image placed at end):" containing the latest draft text with the completed image Markdown appended at the end. While an orphan recovery exists, new replies are blocked and the card is dirty; the user must explicitly choose either `Move to comment` (which transfers the text and image into the root comment draft, provided the root composer is not locked by pending/uncertain/upload work) or `Discard`.
  - _Development (GitHub)_: in the card details sidebar after Contributors (ADR 0064). It lists the pull requests and branches that name the card's task key, or that a member linked by hand, from any connected repository; with none it says so. Nothing polls: a change on GitHub arrives as a hint on the board's socket and the section re-reads.
    - _Pull requests_: one row each with the state icon (open green, draft grey, merged purple, closed red), the title, `owner/name#123 · Open` and an external link, plus an unlink button ("Unlink pull request #123") that removes it from this card only; an unlinked pull request is not linked again by its key.
    - _Branches_: one row each with the branch name, `owner/name`, the short sha and the first line of the latest commit, as an external link. There is no commit history.
    - _Repository, Create branch, Create pull request_: with connected repositories, a **Repository** picker (the card's own repository first) and two buttons. **Create branch** makes the task-key branch from the repository's default branch; **Create pull request** opens one from that branch against the default branch, authored by `foxban[bot]` with "Opened by <name>" in its body, and stays disabled until the card shows a branch in that repository. Success says the result shows on the card once GitHub reports it and links to it on GitHub; a refusal (no commits yet, lost access, rate limit) shows as an inline alert. With no connected repository the section says "No repository is connected. An Admin connects repositories from the GitHub page."
    - _Link pull request_: opens one inline field, labelled "Pull request URL or number", accepting `123`, `#123` or a full `https://github.com/owner/repo/pull/123` URL. A number means a pull request in the repository picked above; a URL can name any connected repository. The link saves on its own submit rather than on the footer Save (the footer says "Pull request link saves with Link pull request." while a draft is open), and a refusal keeps the typed value and an inline alert saying why. Escape walks one rung at a time (clear the field, collapse the composer, then the card's discard guard, which warns "A pull request link is still being saved. Leaving will not cancel it." while a request is in flight). The field and buttons hold at least 44px of hit area under `pointer: coarse`.
  - _Delete_: in the sidebar, under attachments, a muted red **Delete card** swaps itself for the inline recovery warning “Delete this card? It, its subtasks, and everything on them will be kept in Archived cards for 90 days, then permanently deleted.” with **Delete** and **Cancel**. A successful parent delete archives the parent and every active child in one operation; each archived card remains individually restorable. Deleting a child archives only that child. Unsaved title or description drafts are not committed.

## Interface grammar

Foxban uses light neutral surfaces: page headings form the strongest text level, section headings the second, body copy the third, and smaller text carries metadata. Inputs and buttons share consistent dimensions and visible focus rings; text inputs remain at least 16px at narrow widths to avoid mobile viewport zoom. The board's primary New card and creation-submit actions use amber; bordered buttons are secondary, and red identifies destructive/error state as well as the Bug type. Meaningful status and controls meet readable contrast; board appearance and card type colours accompany their icons and names.

Async outcomes remain inline beside the action that produced them — never global toasts — but successes use polite status semantics and errors use alert semantics. Pending actions prevent duplicate submission and say what is happening. At 600px and below, board utilities wrap or move into modal sheets and Kanban columns stack vertically; above that breakpoint the canvas retains intentional horizontal scrolling. Editable controls remain at least 16px at narrow widths (`text-base sm:text-sm`) to prevent iOS viewport auto-zoom, including inline label and checklist inputs. Frequently used coarse-pointer actions expose at least 44px hit areas (`pointer: coarse`), while fine pointers retain compact density. Essential save guidance and key labels are strengthened selectively. Comment and description Markdown prose, code blocks, and wide tables are strictly contained, with wide tables in comments using local horizontal scrolling on mobile rather than overflowing the modal panel.

Foxban has one light application appearance with no theme-switch control or saved theme preference. Board appearance and card type colours coexist with label, priority, due-date, connection, success, warning, and destructive colours, each retaining its domain meaning.

## Drag and drop

dnd-kit (pragmatic-drag-and-drop is the fallback candidate). Cards move within and between columns. Fully optimistic: the card lands instantly and is silently confirmed by the DO echo. On reject or echo timeout the card snaps back — a visible rollback, no toast spam.

During a pointer or keyboard drag, a full-opacity preview retains the source card's measured size above the board, including across column gaps and horizontal scrolling. A faint, stationary source placeholder retains keyboard focus. Release or cancellation removes the preview immediately, independently of mutation acceptance; a peer deleting or archiving its source also removes it. Neighboring cards translate without scaling. The preview uses the same live labels, badges and assignee presentation as the real card and is noninteractive.

## Real-time changes

The other user's edits appear live via WS patches. Per-user cursor streaming remains out of scope, but application-wide online presence, last-seen timestamps, and local time are tracked via a dedicated PresenceDO channel.
## Reconnect UX

Connection state sits beside board identity: `Live` with a green dot, red `reconnecting…` while the socket is down, or red `Could not connect.` when reconnection fails after repeated unsynchronized attempts. Once a board snapshot and workspace have loaded, terminal connection failure does not unmount the workspace or card modal. Local drafts and editors remain mounted. The board header and card modal footer expose **Retry** to restart the connection attempt budget; open creation dialogs expose their own connection **Retry**, still usable while the submitted creation is locked. Creation dialogs use "Reconnecting…" while disconnected and "Checking whether creation completed…" while awaiting settlement. Only an initial connection failure before any snapshot has loaded displays the full-page failure screen. The card modal footer retains "Sync uncertain — reconnecting to verify." while an authored operation awaits resync, or "Not connected — changes won't send." when offline. Nothing is queued or automatically resent: new mutations attempted while disconnected fail fast, while a request already sent remains locked until acceptance, rejection or authoritative verification permits recovery.

Column authorization refusals roll back optimistic changes without a permission toast; an open creation dialog retains its draft and displays the server refusal inline. A legacy socket without a boolean column capability receives an error and closes with `1012`; after reconnect, the rejected column action must be deliberately retried rather than automatically replayed. If reconnection exhausts the existing budget, use the connection **Retry** control first.

## Keyboard shortcuts (milestone 6)

- `n` — open **Create a card** for the first sorted column, with Title focused. No columns: no-op. Opening creates nothing.
- `c` — owner/admin only: open **Add a column**, exactly as **Add column** does, with Column name focused. It creates nothing until submitted. For ordinary members it does nothing and does not prevent the key's default behavior.
- `m` — toggle **Assigned to me**, exactly as the header button does: when inactive it replaces the assignee dimension with the signed-in user's id, and when active it clears that dimension. Search and label filters remain untouched.
- `Esc` — closes Keyboard shortcuts or Filters, or discards an unsent creation draft (an open picker handles Escape first); it cannot cancel a creation already pending. It cancels an archived card's inline permanent-delete confirmation before a second press closes Archived cards and restores its toolbar trigger, or cancels a column-delete alert and restores its ⋯ trigger. In the card view (modal or fullscreen), an open "Edit description?" confirmation takes precedence and Escape cancels only it while leaving the card open; otherwise, it cancels the innermost open editor (description, checklist item, comment, relation query) first, then closes an open attachment preview, cancels an attachment or card delete confirmation, and finally closes the card or raises the discard strip if there is unsaved work (a further press confirms that discard). It also cancels an open inline column title editor without renaming.
- `Space` then arrow keys then `Space` — move the focused card. Cards are focusable and this is dnd-kit's `KeyboardSensor`, so lift/move/drop matches what a pointer drag does; `Esc` cancels a lift.

`n`, `c`, `m`, and `/` are board-level and deliberately unmodified, so they never steal a keystroke: they ignore repeats and modified keys, fire only outside inputs, textareas, selects and contenteditable elements, and do nothing while an overlay is open or a drag is live (a keyboard lift owns the keyboard until it drops). Available shortcuts are advertised by `/` in search, `C` beside Add column, `M` beside Assigned to me, and the **Keyboard shortcuts** dialog, whose Add column row is omitted for members. There is no `?` shortcut. An empty board offers managers the dashed **Add column** control, which carries its `C` keycap; members instead see "No columns yet. Ask a board owner or admin to add one."

The same rule holds for focus that moves on its own. Returning focus to a trigger after a column rename commits or cancels, or after the card view, column-delete alert, Archived cards dialog, Members drawer, Filters, creation or Keyboard shortcuts dialog closes, is a courtesy the user can lose: if the keyboard has already moved on — they clicked or tabbed into another control, or reached for the search field — the pending return is dropped rather than pulling focus back. A restore that fires blindly can swallow the next keystroke, which is exactly how a board shortcut ends up stealing a character meant for a field.

That return also has to find the right control, not merely a control. Closing a card returns focus to that card even when the board has since re-rendered it somewhere else — a peer dragging it into another column replaces the element on this page — because the card is looked up when the restore actually runs rather than when the close began, so the replacement is what receives focus. The return still yields to whoever holds the keyboard on this page: if you have moved on to another control — or focused the search field — in the meantime, it is dropped as above. A teammate acting in their own browser is not a reason to drop it; their change only matters once this page re-renders.
